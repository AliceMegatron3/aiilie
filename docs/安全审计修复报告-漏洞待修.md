## 残余风险与前提

1. **单用户桌面形态**：多项 IDOR/认证/RBAC 在「本机模式」（回环绑定 + `require_auth=false` + 生产启动拒绝危险组合）下被抑制，但未做多用户数据隔离——一旦改为多租户/远程暴露，必须回补阶段 B 的 owner 模型。
2. **隔离 worker 是代码/插件执行恢复的前提**：在低权限容器/worker 未就绪前，代码与插件执行保持 disabled(501)，这是有意的 fail-closed 决策。
3. **密钥轮换与 Git 历史重写为人工运维动作**，须在供应商侧与远端协作者确认后执行。
4. **Ledger authoritative 恢复**：默认关闭，须在真实迁移 + reconciliation 通过 readiness 后由运维显式开启。
