## 二、P2 批次｜稳定性与体验优化

### 2.1 本批次核心优化方向（三大方向，Ollama 探测已移出本批次）

1. **配置容错**：安全默认值、环境变量优先级覆盖、类型错误回退
2. **状态机细化**：标准化全流程任务状态机 + 全链路取消兜底
3. **路由诊断重构**：嵌套路由全量诊断 + 运维入口与响应规范化

### 2.2 P2-1 配置容错（具体范围）

1. **安全默认值**：所有关键配置项增设合规默认值，配置缺失、为空、读取失败时自动加载默认配置，杜绝启动崩溃。
2. **环境变量优先级覆盖配置文件**：明确冲突时的覆盖规则为「环境变量 > 配置文件 > 内置默认值」；任一来源缺失自动下沉到下一级，任一来源非法则按下一级兜底并告警。
3. **配置类型错误时告警并回退**：数值、布尔、字符串等类型格式校验失败时，记录结构化告警（异常字段、非法值、原因），并自动回退到默认合规值。
4. **单项配置异常不影响服务整体启动**：单条配置解析失败仅告警降级，不向外抛出致命异常，服务照常启动；同时保留运行时配置快照与任务级配置副本隔离。

### 2.3 P2-2 状态机细化

- 细化全生命周期任务状态：排队、资源加载中、分段执行中、插件调度中、模型推理中、任务收尾、异常终止、用户取消等。
- 固化状态流转规则：明确各状态前置/后置流转条件与非法转换保护，杜绝状态错乱、回滚、快照丢失。
- 全链路取消兜底：任务取消后管家层同步终止底层模型请求、插件任务、异步逻辑，清除僵尸请求。
- 阶段快照实时留存 + 前端进度精准展示适配。

### 2.4 P2-3 路由诊断重构（具体范围）

1. **统一 /health 健康检查入口**：唯一健康检查路由，全量存活探测统一收口。
2. **增强 404、405、422 等异常响应**：异常响应语义化、状态码规范化，便于前端与调用方精准处理。
3. **增加并贯通 trace 追踪信息**：请求/任务全链路 trace 标识贯穿路由、日志、异常响应。
4. **统一错误响应结构和日志关联字段**：错误响应结构统一，日志统一关联 trace_id、task_id、stage_id。
5. 递归遍历 include_router 嵌套路由，形成全量路由台账，新增重复/无效/冲突路由检测。

### 2.5 P2 验收标准

- ✅ 配置体系容错完善：非法配置不炸服务、单项异常不影响启动、并发配置无污染
- ✅ 任务状态机精细化落地：状态流转规范、取消全链路兜底、无僵尸请求残留
- ✅ 路由诊断无盲区：嵌套路由全量识别、/health 统一、异常响应增强、trace 贯通
- ✅ 完全兼容 P0/P1 落地成果，无旧问题复现

## 三、P3 批次｜细节优化增强

### 3.1 本批次核心优化方向（四项方向）

1. **全链路结构化日志改造**：任务ID、阶段ID、请求ID全绑定，故障精准溯源
2. **双模型负载均衡与拥塞拦截**：负载预判、拥塞拦截、智能择优切换
3. **长任务分层超时与卡死熔断**：三级分层超时、卡死检测、自动熔断释放
4. **Ollama 探测真异步化**：异步 HTTP 客户端、后台任务、重试退避、状态缓存

### 3.2 P3-1 全链路结构化日志改造（溯源运维专项）

- 全链路ID贯穿绑定：任务ID为核心主键，关联阶段ID、请求ID、模型调用ID，覆盖全流程。
- 日志结构化标准化：JSON 结构化日志，字段含时间戳、任务ID、阶段、状态、错误码、请求参数、耗时、模型类型、异常堆栈。
- 异常日志精准归类：网络/模型/参数/超时/配置/权限六大类报错自动标记。
- 模型调用日志专项：记录入参规模、Token消耗、重试次数、切换记录、响应耗时。
- 日志级别精细化：DEBUG/INFO/WARN/ERROR 四级，过滤冗余、保留核心运维信息。

### 3.3 P3-2 双模型负载均衡与拥塞拦截（资源调度专项）

- 模型负载状态实时采集：本地模型并发数、队列积压、响应耗时、硬件占用 → 动态负载评分。
- 拥塞阈值智能判定：负载/队列/超时阈值达标自动暂停本地任务下发。
- 无重复择优切换：杜绝双向并行调用、重复请求，拥塞场景无缝切换云端承接。
- 负载恢复自动回切：本地负载回落后自动恢复本地优先调度。
- 调度日志专项记录：切换时机、负载数据、切换原因形成调度台账。

### 3.4 P3-3 长任务分层超时与卡死熔断（运行上限专项）

- 三级分层超时：连接超时、单步推理超时、全局任务超时，差异化阈值适配短/中/长任务。
- 任务卡死检测：长时间无进度更新、无日志输出自动判定卡死。
- 自动熔断与资源释放：终止全链路执行，清空底层模型请求、插件进程、异步任务。
- 熔断预警与日志留存：记录熔断原因、任务时长、资源占用、任务快照。
- 正常任务兼容保护：合理时长复杂长任务不受影响，仅拦截异常常驻、卡死、阻塞任务。

### 3.5 P3-4 Ollama 探测真异步化（启动链路增强专项）

**当前事实口径（已完成治理，勿视为待治理问题）**：

- ✅ Ollama 探测已迁移到 lifespan 生命周期阶段
- ✅ 探测已具备有界超时（2.0s）
- ✅ 探测失败时仅记录告警
- ✅ Ollama 不可用不会阻塞主服务启动

**本项定位**：非阻断性异步化增强项，仅将同步探测调用升级为真正的异步实现并补充后台重试退避与状态缓存。以下过时描述不再作为现状根因：探测卡住事件循环、探测导致启动卡顿、探测导致偶发启动超时、探测失败阻塞服务启动——均已在前序批次完成治理。

**具体内容**：

1. **异步 HTTP 客户端替换**：使用异步 HTTP 客户端（httpx.AsyncClient 或 aiohttp）替换当前同步 Ollama 探测调用，不再使用同步网络调用阻塞事件循环。
2. **后台任务执行探测**：将 Ollama 探测放入后台任务执行，不阻塞主业务请求、避免影响主业务链路。
3. **失败重试与退避机制**：探测失败按照退避策略进行有限重试。
4. **探测状态缓存与结果记录**：增加探测状态缓存及最近一次探测结果记录，探测结果与当前状态可缓存、可查询。
5. **降级行为保持**：探测失败时保持既有降级行为（仅记录告警、默认标记模型不可用、倾向云端兜底），不影响主服务正常运行。

### 3.6 P3 验收标准

- ✅ 全链路日志结构化、全ID贯穿绑定，故障可精准溯源、可检索、可归类
- ✅ 双模型负载均衡生效，拥塞自动拦截、智能择优切换，无重复调用、无算力浪费
- ✅ 长任务分层超时、卡死熔断机制正常生效，无常驻僵尸任务、无算力泄漏
- ✅ Ollama 探测使用异步 HTTP 客户端，不再使用同步网络调用阻塞事件循环；探测通过后台任务执行，不阻塞主业务请求；探测失败按退避策略有限重试；探测结果与状态可缓存查询；Ollama 不可用、探测超时或重试耗尽时仅记录告警并保持主服务可用；现有 lifespan 探测、有界超时、失败告警、启动不阻塞行为不得回退
- ✅ 完全兼容 P0/P1/P2 所有稳定成果，无旧问题复现、无架构逻辑冲突
